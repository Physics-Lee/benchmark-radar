2关键设计决策

D1. 采用域标签不动评分，走独立规则段

taxonomy: 每命中一类 +20 relevance 且授予发布资格（rubric.py:66-68）。把 neuro/BCI 塞进 taxonomy 会污染分数可比性与 category 趋势。因此新增独立 science_domains: 配置段 + 独立匹配器，语义与 watchlist 一致：路由 / 筛选信号，不是质量声明。

D2. 采用标签在 classify 期派生，40 天历史立即生效

dashboard_data（snapshots.py:854-1003）在 870–878 行做记录富集，已有先例（organizations 在此重算）。在此对每条记录的 title + summary 跑确定性域匹配，写入 science_domains: [...]。不写回快照、不动快照 schema（附加字段可通过校验），历史全部立即带标签——tab 上线首日就有内容。

D3. 采用字段命名 science_domains，避免撞名

UI 与策展层已有两个 "domain" 概念（model_cards 每 bench 的 domain 字段、Leaderboard 的 ldomain 外部目录筛选）。science_domains 自解释且无歧义。

D4. 采用规则精度红线（用测试锁死）

  • neural network(s) 不得触发 neuroscience——这是最高频误报源。
  • BCI 域用强信号词：brain-computer interface、词边界 \bBCI\b、motor imagery、EEG decoding 等。
  • neuroscience 域用词干与术语：neuro*、EEG / MEG / ECoG / fMRI、neural decoding、spiking、neuron、connectome 等。
  • 规则放 config.yml，匹配器纯函数化（无外部模型调用，与 CI 的确定性约束一致），便于手审样本回归。

决策点裁决说明

D6. v2 新增查询面与展示面共用同一派生函数（修复 review 发现的 BLOCKER）

QueryService 的 Radar 候选直接读原始快照（query.py:368-391），字段逐一手工映射（query.py:412-446，425 行的 categories 即照抄快照字段）。若只在映射处抄一个 science_domains 字段，40 天历史在本地查询 / CLI / 离线客户端永远返回空数组——一个"测试绿但不可用"的契约。因此：

  • dashboard 与 QueryService 调同一个 derive_science_domains() 纯函数（输入 title/summary 在 query.py:423-424 现成）；
  • 离线数据包在 build-data-release 时把派生结果烘焙进产物（快照副本或 manifest 携带），安装的客户端不依赖 config.yml 规则；
  • 验收测试必须用真实历史标题断言产出 neuroscience / bci，不得只断言字段存在。

8CI 与 PR 纪律 / 执行顺序

每个 PR 开出前，在干净 checkout（git worktree add --detach <tmp> <branch>）跑六步全绿：

ruff check .
ruff format --check .
benchmark-radar normalize-external
benchmark-radar classify
benchmark-radar build-data-release
pytest -q

PR 用 merge commit，不 squash。

执行顺序：PR1 → PR2 → PR3a（#512）→ PR3b（新 view）串行，导航 6→5→6。PR3b 依赖 PR1 的数据字段与 PR3a 腾出的导航位；PR2 独立可并行，但测量建议在 PR1 合并后做，避免基线漂移。产出之外，把基线数字与测量结果整理成双语 issue 评论发到 #511，作为"深度讨论"交付（发帖前需确认）。
